一闪而过 / 没反应 脚本跑完了但你没看清。窗口最后一行写着结果；实在没看到就打开 推送日志.txt。重跑是安全的，本地提交不会丢。

STEP 05 把包装进手机（真机验证用）

5

用 Sideloadly 装到 iPhone

不花钱，用你自己的 Apple ID 签名。7 天过期，Sideloadly 会自动续签。

⚠
先说清楚这条路验不到什么。这个 App 的「通知里打标」和「分享进来」， 靠的是 App Group（跨进程共享容器）。免费 Apple ID 签出来的包 很可能带不上 App Group —— 所以第 1 / 2 / 22 条大概率验不了； 第 6~9 条（配图管线）和其余单进程的条目不受影响。 看到 application-groups 的报错，不用怀疑代码，那是账号能力的问题。 三条路的代价对照在 编译预检清单 6.0 节。

第 1 步 · 装两个「网页版」的 Apple 组件

Sideloadly 靠苹果官方的驱动跟手机通信，而它不认 Microsoft Store 版的 iTunes / iCloud —— 装了那种要先卸掉，否则连不上手机。

  1. 先到 设置 › 应用 › 已安装的应用 里看有没有从商店装的 iTunes 或 iCloud，有就卸载。
  2. 到 Apple 官网下载页装 网页版的 iTunes（找「Windows 版」，不是商店那个）。
  3. 同样装 网页版的 iCloud for Windows。

第 2 步 · 下载 Sideloadly

只从官网 sideloadly.io 下，别走第三方下载站。选 Windows 64 位。 它是一个绿色小程序，不装系统服务。

第 3 步 · 把 IPA 下下来（这一小步有个坑）

  1. 打开 github.com/haohao234/She/actions，点最新那次绿色勾的 run。
  2. 页面拉到最下面找 Artifacts 区，下载 HerInfo-ipa。
  3. Artifacts 必须登录 GitHub 才能下，仓库是公开的也一样（这是 GitHub 的规矩，不是权限没给）。 手机上直接点会下不动，用电脑浏览器登录后下。
⚠
这东西要解压两次，拖错一层就会报 Invalid file。 GitHub 的 Artifacts 自己是个 zip；把它解开，里面才是我们要的 HerInfo-<提交号>-unsigned.ipa。
→ 要拖进 Sideloadly 的是那个 .ipa； 不是 HerInfo-ipa.zip，也不是被解压开的 Payload 文件夹。
→ 顺手把它放进一个纯英文路径，比如 C:\ipa\ —— 路径里有中文也是报 Invalid file 的常见原因。
i
文件名里的 unsigned 是故意的。云端那台机器上没有任何签名身份， 它签不了 —— 签名这一步由 Sideloadly 在你这台 Windows 上用你的 Apple ID 做。 IPA 本身没有魔法：就是「一个叫 Payload 的文件夹里放着 .app」再打包，不签名也能打。

第 4 步 · 先切到本地 Anisette Server（国内基本必做）

Sideloadly 跟苹果服务器打交道时，需要一组由 Anisette Server 生成的参数。 它默认用官方那个远程服务器 —— 那个要捐赠才能用，而且在国内常常连不上。 连不上的表现是签名还没开始就失败，日志里会出现 Obtaining team ID 之类的字样，以及一些看不懂的十六进制错误码。这一步花两分钟，能省掉后面一大圈排查。

  1. 点界面上的 Advanced Options 展开高级选项。
  2. 找到 Anisette Server 那一栏，点 Download 把本地服务下下来（一次性）。
  3. 下完在左侧选中 Local —— 这一步必须点，只下载不切换等于没做。

第 5 步 · 装

  1. iPhone 用数据线连上电脑，手机上点「信任此电脑」。
  2. 打开 Sideloadly，把那个 .ipa 拖进窗口。
  3. 在 Apple ID 那一栏填你的 Apple ID —— 免费账号就行。
  4. 确认上面显示的设备是你的 iPhone，点 Start。
  5. 它会要两次验证码（双重认证），按手机上收到的填。这是正常的，不是出错。

第 6 步 · 手机上还要开两个开关（漏了会「装上了却打不开」）

  1. 开发者模式：设置 › 隐私与安全性 › 开发者模式 → 打开 → 手机会要求重启一次。iOS 16 及以上必须有这一步，而且这个开关 只在插过电脑之后才会出现。
  2. 信任证书：设置 › 通用 › VPN 与设备管理 → 点你 Apple ID 那一条 → 信任。
  3. 回桌面，她的信息本应该就能打开了。
▸
7 天过期是免费账号的硬限制 —— Apple 官方写的是 10 个 App ID / 3 台设备 / 描述文件 7 天。 Sideloadly 自带自动续签：在它的设置里打开自动刷新，之后只要电脑和手机 在同一个 Wi-Fi（或者插着线），它会在到期前自动重新签好，不用你管。

万一失败：先按报错原文找

⚠
Sideloading failed! Invalid file / Install failed: Guru Meditation … —— 最常撞的一个。 它不是「苹果拒绝了你的包」，而是在说「我读不出我手上这个东西」 （那句十六进制只是 Sideloadly 自己的内部编号，不是诊断信息）。 按下面这张表逐条排，多数在前两条就好了。
1拖错东西了 —— 必须拖解压后的 .ipa。拖 HerInfo-ipa.zip、或者把那个 zip 改名成 .ipa，都会报这个（因为里面没有 Payload 这一层）。
最容易犯的一条，先看它。
2Anisette 没切到 Local（第 4 步）—— 这个失败报的也是 Invalid file，很容易误以为是包的问题。国内网络下它是高发项。
3文件没下全 —— 中断过的下载，zip 能打开但解压缺东西。重新下一次；下完先自己解压一遍，能解出 Payload 文件夹才算好。
4路径里有中文或空格 —— 把 .ipa 挪到 C:\ipa\ 这种纯英文目录再拖进去。
5Sideloadly 版本太旧 —— 到官网 sideloadly.io 下最新的。苹果那边一改，旧版本就会读不懂返回的东西。
6换网络试 —— 关掉代理，或者改用手机热点。这个错在国外论坛上有一模一样的十六进制码，当事人试遍手里所有 IPA 都没用，最后是换网络解决的。
7还不行，就把扩展去掉再试 —— Sideloadly 高级选项里有 Remove App Extensions（也可以解开 IPA、删掉 Payload/HerInfo.app/PlugIns 再压回去）。
代价写清楚：去掉扩展 = 通知打标与分享两条线彻底没得验。但在免费账号下它们本来就是哑的（App Group 带不上），所以这一步换来的是「主 App 至少装得上、能跑」——是否值得由你定。
i
包这一侧的问题已经堵掉了。上面那个版本的包里其实有两个真毛病： 三个 bundle 都缺 CFBundleVersion（安装校验的必填项）， 而且它是 Debug 配置 —— 带着一个 7.7 MB 的调试动态库， 主程序只剩 71 KB 的壳。 现在流水线改成 Release 构建、补齐版本号， 并且多了一步拆包自检：这两样再出问题，CI 会直接红， 坏包不会变成你能下载的 artifact。

报 application-groups

  • 原话大致是 None of the valid provisioning profiles allowed the specified entitlements: com.apple.security.application-groups
  • 这是账号能力问题，不是代码问题。
  • 包一般还是能装上（带不上的 entitlement 会被去掉），只是通知打标、分享进来那两条线是哑的。
  • 想真验那几条，只能换路：借一台 Mac，或者付费开发者账号。

装上了，但扩展是哑的

  • 表现：通知里长按没有那个展开界面；分享面板里没有「她的信息本」。
  • 两个可能：扩展没被嵌进包里（云端那步会打印 PlugIns 列表，去核对），或者 Bundle ID 前缀对不上。
  • 用 Sideloadly 的「改 Bundle ID」时，两个扩展的 id 必须跟着改前缀 （现在是 com.herinfo.app.notification / com.herinfo.app.share）， 前缀对不上扩展就不加载，而且不报错。
i
上面七条都排完还是不行，就把 Sideloadly 的完整日志整段贴回来 —— 点右下角那个按钮能展开。它比界面上那两行详细得多。
贴的时候把那两行原文一起带上：Sideloading failed! 后面跟的 那句话（比如 Invalid file）比一串十六进制有用得多 —— 十六进制是 Sideloadly 内部的编号，同一句话在不同的十六进制码下面都出现过。

AFTER 编译过了之后

编译通过只是个门槛，而这个门槛早就过了 —— 第 4 轮起连续 22 次成功， 36 屏和三个 target 全部落地。流水线现在还会顺带产出一份可侧载的 IPA。 所以现在只剩一件事：真机验。它缺的不是清单，是通道。

1先解决「包怎么进手机」
CI 产出的是不签名的 .app，装不进真机。预检清单 6.0 节列了三条路（借 Mac / 付费开发者账号 / Sideloadly）各自的代价，以及那条硬卡点 —— 这个 App 的跨进程通信全靠 App Group，而免费 Apple ID 很可能签不出带 App Group 的包。
2过一遍预检清单第 6 节的 22 条
其中第 6~9 条（配图管线）只能在真机上验，模拟器连相册选择器都测不到；第 1 / 2 / 22 条依赖 App Group。失败方式都很安静 —— 不报错，只是白做。

总结成一句话

建一个空仓库（三个勾都别勾）→ 在 她的信息本-iOS 目录里 git remote add 再 git push → 等 Actions 跑完 → 把 error / warning 两段贴回来。

卡在任何一步，把屏幕上的字贴给我就行。
