第 2 步 · 跟着窗口走，最多回答两个问题

新版流程是先诊断、再推送。窗口会依次做六件事，每做完一件都把结果打出来 —— 所以任何一步出问题，你都当场知道是哪一步、什么原因。

它会做为什么要这么做
① 找到 git 这台电脑上 git 不在系统 PATH 里（也因此没有 Git Bash 可开）。 脚本按「便携版 → 正式版 → PATH」三个位置依次找，不依赖任何环境配置。
② 进入仓库目录 用脚本自己的位置定位，不写死路径 —— 所以它必须待在 她的信息本-iOS/ 里，挪出去就认不到了。
③ 确认是仓库 + 报本地状态 顺便告诉你本地有几个提交、工作区干不干净 —— 推送前心里有数。
④ 检查有没有代理 代理是最隐蔽的一类原因：它不在 git 里，配错了报错却长得像网络问题。
⑤ 先测地址，再推送 这是新版最重要的改动。它用 git ls-remote 单独试一次连接，把 git 的原始报错原样打出来， 再按「找不到仓库 / 登录被拒 / 网络不通」分别给处置办法。 找不到仓库时，还会顺手列出你账号下真实存在的仓库名。 连不上时它先原地自动重试，不会一遇到超时就判你「网络不通」。
⑥ 看远程空不空，然后推 远程非空就会先告诉你远程上有什么，问你要不要覆盖 —— 而不是等你撞上 rejected 再自己猜。
▸
地址在哪拿：打开仓库网页，浏览器地址栏里那一行就是最准的 （比点绿色 Code 按钮更不容易拿错）。 形如 https://github.com/你的用户名/仓库名 —— 结尾的 .git 有没有都行。

我已经把本地仓库的地址改成 …/haohao234/She.git 了， 所以窗口弹出来时直接按回车就行。如果那不是你要的仓库， 在窗口里粘贴正确的地址再回车，脚本会当场验证给你看。

窗口里出现红字，对着这张表看

窗口里的话判断 · 怎么办
Repository not found 地址里的用户名或仓库名不对。脚本会当场列出你账号下的仓库名，对着改。 注意：私有仓库若登录没成功，报的也是这一句。
rejected / fetch first 远程不是空的（建仓库时勾了 README / .gitignore / License）。 脚本会先问你要不要覆盖 —— 自动生成的 README 覆盖掉没有损失。 想彻底干净，就删掉仓库重建一个「三个勾都不勾」的。
Authentication failed 登录没过。重跑一次；若弹的是「用户名 / 密码」框，密码栏填 Personal Access Token（见下方说明）。还不行就清掉旧凭据再试。
Failed to connect / timed out / Connection was reset 这一条基本都是「一阵一阵的」，先重跑再说。 脚本 v3 遇到这类错误会自动等 4–5 秒重试，最多 3 次 —— 实测同一台机器，21 秒连接超时之后过几分钟原样重跑就通了。 三次都没通，脚本才报「网络不通」；那时再换手机热点最快。 不要去改地址、也不要重新登录，那跟这件事没关系。
CONNECT tunnel failed / 502 代理的问题。你开了代理 / VPN 但它没在正常运行，或不放行 github.com。 脚本遇到这类错误会自动再试一次「绕开代理」的直连 —— 而且只在网络类错误时才绕，免得把地址写错误诊成网络问题。
一闪而过 / 没反应 脚本跑完了但你没看清。窗口最后一行写着结果；实在没看到就打开 推送日志.txt。重跑是安全的，本地提交不会丢。
▸

PLAN B 如果 GitHub 打不开

GitHub 在国内时快时慢。如果你连仓库都建不上、或者 git push 一直超时， 别在这上面耗 —— 换下面任一条。

走代理 如果你本机有代理，给 Git 单独配一次即可：
git config --global http.proxy http://127.0.0.1:端口
和你平时浏览器用的那个端口一致
Codemagic 专做移动端的云 CI，注册后可以直接上传项目压缩包，不一定要走 GitHub。免费额度 500 分钟/月。 代价是要在它那边重新配一次构建命令 —— 需要的话我来写它的配置文件。
找一台 Mac 借朋友的、或租一台云 Mac（按小时计费）。
在这台 Windows 上装 macOS 是违反 Apple 许可协议的，而且极不稳定 —— 我不建议把项目押在这上面。
